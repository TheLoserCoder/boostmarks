# Boostmarks: переработка менеджера по референсу Stitch

Источник: `C:\Users\PC\Downloads\stitch_windows_explorer_interface_design.zip` (`screen.png`, `code.html`), изучен 2026-09-27. Это ориентир композиции и цветовой палитры, **не готовый компонент и не точная копия**. Не копировать чужие файлы/папки, облачные статусы, действия ОС, даты и фиктивные кнопки: отображать только существующие возможности Boostmarks и данные нативных закладок. Не подключать Tailwind CDN, удалённые шрифты или Lucide CDN в расширение; использовать `lucide-react`, локальный CSS и существующие компоненты.

## Диагностика и исходное состояние

- Открытая сборка в отдельном профиле Chromium: `manager.html`, вид «Список», одна закладка `Chrome Web Store` в `Other bookmarks`; видны две корневые папки, но нет очевидной папки назначения внутри списка. Менеджер почти пустой и белый, поэтому не демонстрирует работу перетаскивания. Это **не доказательство**, что нативная команда не вызывается; E2E с подготовленными закладками проходят. Нужна проверка жеста в реальном профиле пользователя и разбор отказов, а не утверждение о найденной причине.
- `DragItem.tsx`: перетаскивается только маленький `GripVertical` с `tabIndex=-1`; нет `DragOverlay`, видимого перемещаемого объекта и явного индикатора невозможной цели. `FolderContent.tsx`: цели только текст папки либо текст закладки. `QuickLinks.tsx`: папки — цели, но их назначение не объяснено. `BookmarkExplorer.tsx`: визуальное подтверждение появляется лишь после завершения команды; наведение при перетаскивании мало заметно.
- Текущая композиция: заголовок страницы над боковой панелью; путь, поиск, вид и «Новая папка» в одной строке внутри содержимого; нет разделения навигационной и командной полосы, нет секции карточек домашней страницы, мало визуальной иерархии. `app/ui/tokens.css` по умолчанию следует теме ОС, а референс явно тёмный.
- Референс: верхняя область вкладок/заголовка (не имитировать системные кнопки окна браузера); ниже строка «назад / вперёд / вверх / обновить — путь — поиск»; затем компактная командная панель; фиксированная тёмная боковая навигация; для домашнего представления карточки закреплённых папок над содержимым; снизу компактный список и строка состояния. Основные цвета из HTML: chrome `#181818`, content `#202020`, sidebar `#1c1c1c`, текст `#f3f3f3`, вторичный `#9a9a9a`, акцент `#60cdff`, мягкое выделение `rgba(255,255,255,.08)`. Контраст проверить в реальной сборке: не переносить альфы и мелкий шрифт 13px автоматически.

## Приоритеты и последовательность

### P0 — прежде визуальной миграции: сделать перенос воспроизводимым и понятным (существующая 3.5)

1. Завести контрольный набор в изолированном профиле: две папки, вложенная папка, несколько закладок; отдельные сценарии для списка, таблицы, сетки и цели в боковой панели. Проверить в уже открытом Chromium сценарий пользователя: за какую область тянет, активируется ли сенсор, куда наводит, есть ли разрешённая цель, что возвращает команда. Не изменять личные закладки без согласия.
2. Расширить область захвата с маленького маркера на тело строки/карточки, **сохранив** single-click selection, double-click open, ссылки, pin, контекстное меню и marquee; порог движения отсекает случайный drag. Для выбранной группы определить явное правило (либо реализовать атомарно/последовательно с отчётом об ошибке, либо не обещать групповой перенос); не переносить скрыто только один элемент.
3. Добавить видимый `DragOverlay` с иконкой/названием/счётчиком, яркие состояния разрешённой и запрещённой цели и линию позиции «перед», скролл при подводе к краю и ясное сообщение при отмене/отказе. Подсказка при первом взаимодействии или короткая доступная подпись «Перетащите в папку; для клавиатуры — Переместить…»; не показывать нативные ID.
4. Уточнить идентификаторы областей при одной и той же папке в списке и sidebar, проверить самоперенос, потомков, управляемые узлы, устаревшую проекцию, неуспешную команду. Источник истины — `browser.bookmarks`; при неуспехе нет ложного успешного состояния, при событии `onMoved` сверить отображение с проекцией. Оптимистичный слой — только с определённым откатом/таймаутом, иначе оставить честное состояние ожидания.
5. Приёмка P0: пользователь с подготовленными закладками может перетащить строку без поиска маленького маркера, видит объект и цель, результат появляется сразу после нативного подтверждения; мышь, touch/pointer где поддерживается, контекстное меню/клавиатура и отказы протестированы. Отдельный ручной прогон в Chromium; Firefox runtime — в задаче 7, а не подмена Firefox lint.

### P1 — каркас, дизайн-токены и основные экраны (новая задача редизайна)

6. Зафиксировать карту UI: верхняя **внутренняя** шапка «Закладки» (не системные кнопки и фиктивные вкладки), отдельная навигационная строка (назад/вперёд/вверх/обновить, breadcrumb/редактируемый путь, поиск), под ней панель реально поддерживаемых действий («Новая папка», меню вида, доступные операции с выделением). Недоступные команды не рисовать ради сходства со скриншотом. Сохранить семантику кнопок, истории навигации и `Escape`.
7. Перенести палитру в `app/ui/tokens.css` через семантические токены (chrome, sidebar, surface, hover, selected, border, text, accent, focus). Темная тема по образцу; светлая и системная — совместимые варианты, без потери forced-colors/reduced-motion. Использовать локальный стек Segoe UI Variable/Segoe UI/system. Проверить контраст текста, второстепенных меток, границ, фокуса, drop target и ошибок в обеих темах.
8. Перестроить `ManagerApp`, `shell.css`, `BookmarkExplorer.tsx` и разнести стили по зонам, не копировать весь HTML. Sidebar 240–260px: корни, закреплённые папки, дерево по мере надобности, явное выделение открытой папки, доступные названия, управление закреплением; не изображать «This PC», OneDrive или реальные диски, если источников данных нет. В узком окне sidebar сворачивать/переключать осмысленно, а не забивать полэкрана.
9. Домашнее представление только из существующих данных: карточки закреплённых и верхнеуровневых папок с иконками/краткими подписями; список «Недавние» только если достоверен источник времени/активности (bookmark `dateAdded` ≠ время посещения). Не рисовать «Shared»/«Favorites» как фальшивые вкладки. При открытии обычной папки — её реальное содержимое, без карточек поверх списка. Empty state показывает создание папки и пример перемещения, а не пустой экран.
10. Список/таблица/сетка: плотность, типографика, заголовки столбцов, selection/hover/focus, статус снизу, хорошие усечения длинных названий/URL. Не уничтожать TanStack Virtual и ARIA роли; при изменении высоты строк обновить виртуализатор и тесты, для сетки >50 — подзадача 3.9. Одна система иконок `lucide-react`; favicon можно добавить отдельно с fallback, не делать CDN зависимостью.

### P2 — доработка UX и выпуск

11. Адаптировать popup/options к общей палитре и контролам, но **не** превращать компактный popup в копию менеджера. Связать темную/светлую/system и ru/en с уже ожидающей 3.7, не дублировать слой локализации. Сохранить пользовательский выбор вида и быстрых ссылок.
12. Сквозные проверки: тесты поведения прежде каждого изменения; скриншоты менеджера с контрольным набором в широкой/узкой ширине и обеих темах; контраст, видимость фокуса, keyboard-only сценарии, скринридерные названия, reduced-motion/forced-colors; окно браузера с реальной установленной сборкой. `npm run check`, Chromium E2E, Firefox build/lint, отдельный Firefox runtime согласно задаче 7. Проверить 50k-проекцию и крупную папку — число DOM-строк ограничено, прокрутка/фокус работают.

Тёмная палитра — значение по умолчанию (`:root`), светлая — `[data-theme='light']`, явный тёмный атрибут — `[data-theme='dark']`; системное следование и переключатель подключаются в задаче 3.7. Выделение строки — нейтральная заливка плюс акцентная полоса слева (как в Проводнике), у плитки — акцентная рамка.

## Что не копируем из шаблона

Фальшивые вкладки и системные кнопки окна, «This PC»/диски/сеть, облачные статусы и значки синхронизации, фильтры и сортировку без данных, кнопку «Details», внешние CDN (Tailwind, шрифты, Lucide) и любые фиктивные действия. Верхняя шапка остаётся внутренней шапкой страницы, а не имитацией окна.


## Зависимости и критерии завершения

- P0 разблокирует удобный ручной просмотр; визуальные токены → каркас → домашняя страница и контент → интеграционные проверки. Параллельно допустимо делать безопасную токенизацию и визуальный прототип, но не объявлять работу готовой, пока DnD не проверен пользователем.
- Не менять доменные правила, typed messages и Dexie ради вёрстки. Компоненты получают данные/колбэки, use cases не импортируют UI. Не импортировать `code.html` в runtime; архив остаётся внешним источником, план и палитра — в проекте.
- Готово, когда пользователь подтверждает стиль на скриншоте с **реальными** демонстрационными данными и может переместить закладку интуитивно; нет фиктивных действий, регрессий выбора/навигации/создания папок, E2E проходят после перезапуска установленной сборки.
